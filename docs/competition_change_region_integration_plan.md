# 变化定位接入方案：原始描述与后置约束解码

本轮只实现本地 LoRA 实验，尚未改变正式 planner、模型路由或网站服务的答题逻辑。

## 本轮实验

同一份 Qwen3-VL-2B + checkpoint-3406 LoRA，顺序执行两个阶段。第一阶段复用原评测的 Qwen3VLDataCollator、基础模型 processor 默认图像预处理、max_seq_length=1024、SDPA、bf16、贪心生成和上限 128 tokens。第一阶段保留原始多模态 KV，第二阶段继续使用同一份含视觉 token 和自由描述的缓存，不重新编码双图，不改成仅根据描述的文本判断，也不克隆 KV。测试期间只有一个模型驻留显存。

1. 只使用原 LEVIR-CC 提示词，不附加网站问题、位置要求或候选集合：

   ```text
   The first image is before the change and the second image is after the change. Describe all visible changes concisely. If there is no change, state that clearly.
   ```

2. 在原多模态缓存上追加下列后缀，以十个标签构建 tokenizer 前缀掩码，实际限制每步可生成的 token；完整标签后才允许 EOS。此时模型仍可通过 attention 使用原图视觉信息，描述没有写方位也不会导致图像上下文丢失。缓存沿用原 Qwen M-RoPE 位置状态，顺序原位推进，用完即释放。

   ```text
   Question: {request.question}
   Return only one location: top_left, top, top_right, left, center, right, bottom_left, bottom, bottom_right, no_change (no_change means no visible change).
   Answer:
   ```

25 组已标注开发图按 23 组清晰标注统计区域准确率；2 组 unclear 不计入。另取前 5 组的 BEFORE 图组成 A/A 同图对，单独检验 no_change，不能替代真实无变化评测。描述正确率留给人工复核，不以区域答案正确率代替。

正式区域测试前，抽取用户提供的 `predictions_levir.jsonl` 历史图片进行逐字复现核对，并分别保存历史输出、本机原评测输出和缓存自由输出。缓存自由输出必须与未改动的原评测生成一致；本轮也要求历史抽样一致才继续区域测试。每组开发图片另运行原评测生成作一致性校验，该额外校验顺序执行并释放临时结果，不属于答题链的第二次视觉预填充。历史复现与区域准确率分别报告，不能因提示词相同就宣称历史结果已经复现。

## 主要变化方位提示词对照实验

后续 `primary_location` 实验只改变第一阶段提示词，让训练得到的变化描述能力主动提供主要变化的图中方位：

```text
The first image is before the change and the second image is after the change. Describe the main visible change and its location in the image concisely. If there is no change, state that clearly.
```

第一阶段仍自由生成，十个候选和网站原问题均在生成结束后才注入。沿用同一 LoRA、预处理、128 tokens 贪心生成、后置提示词和约束解码。使用上一轮已完成的 25 组开发题和 5 组同图对照作为基线，启动前核对所有双图顺序、问题、输出契约和模型配置；报告并排展示描述与最终标签，分别统计区域得分、无变化对照、改善与退步条目。新提示词有意改变生成内容，因此不再要求它复现旧提示词的历史描述；也不重新执行此前已完成的一致性检查。本实验仍不改正式服务的答题逻辑。

## 概率诊断与三轮重放

诊断实验保持主要变化方位提示词与贪心解码，重复 3 轮同样的 30 组输入，记录每一步合法 token 的 logits、完整词表 softmax 概率和合法 token 集内的归一化概率。共享 token 前缀的标签共享一个分支，不能把首 token 的概率误写成完整标签概率。同时记录未约束 top 10、合法 token 的原始总概率及对数总概率、候选分词、后缀空格和拼接分词是否一致。

另顺序评分十个完整标签，保存各 token 对数概率、EOS 对数概率、联合得分及归一化值，并保留不含 EOS 和长度平均的对照分数。这些是文本候选的相对似然，不是答案正确的概率，也不用于改变此次实际贪心选择。候选之间使用 DynamicCache.crop 回退到同一个后缀前缀，无视觉重新预填充、无 KV 克隆，诊断默认关闭。概率专表为 probabilities.jsonl，报告每轮更新，进度每组更新。

自由描述按原双图分别复核变化内容和位置；复核来源、具体依据与不确定项保存在独立文件。新重放只有有序图像 SHA256 和描述逐字相同才沿用复核，否则标为待复核。三轮重复不能当作三个独立数据集，主观图像复核也不等同官方标准答案。

## 九区域解码边界修复与四方案对照

### 已确认并修复的问题

旧的 `decode_from_cache` 将答案后缀与候选标签分开分词，再把两段 token ID 拼起来。Qwen tokenizer 会把后缀末尾的空格与首个答案词合并：例如完整文本 `Answer: top_right` 中，候选从带前导空格的 `Ġtop` 开始；单独编码 `top_right` 得到的序列不能代表这个上下文。旧候选掩码因此屏蔽了模型实际可生成的 token，并把剩余合法 token 的概率重新归一化。

修复后，对完整的“答案后缀 + 候选标签”分别联合分词，只将候选共有且不越过后缀边界的最长 token 前缀追加到 KV；每个候选从该前缀之后保留自己的完整 token 序列。候选原始对数似然逐 token 累加，并在标签完整后另计 EOS；不同长度候选各自评分，候选之间仍通过 `DynamicCache.crop` 回到同一 KV 长度。贪心掩码与评分使用相同的上下文 token 序列，不复制 KV。

本地 Qwen tokenizer 检查显示，后缀独立编码以 `Ġ` token（ID 220）结尾，而联合编码会让答案分支以 `Ġtop`（ID 1909）或相应方位 token 起始。单元测试覆盖九个区域标签、`top_right`/`center` 的实际解码、前导空格边界、共享前缀标签、不同标签长度、EOS 似然和 prompt-only KV 预填充。

### 待实验验证的假设

解码边界修复确认了候选 token 序列一致性；它本身不证明定位准确率会提高。下列四种路径使用同一模型和开发图片作配对比较：

| 方案 | 定义 |
| --- | --- |
| A | 使用现有主要变化及方位自由描述提示词，保留双图与描述 KV 后约束输出九区域标签。 |
| B | 双图直接预填充，不生成自由描述，再约束输出九区域标签。 |
| C | 先生成同一变化描述，第二阶段只输入描述文本和问题，不复用图像。 |
| D | 双图原尺寸叠加纯红 2 像素九宫格线，直接约束输出九区域标签。 |

另取 5 组 A/A 相同图片作为 no-change 控制；这些控制只测试 `no_change` 识别，不计入九区域准确率。报告逐题保存参考标签、答案、错误类型、九个区域候选的原始分数和分阶段耗时。已有人工描述评审只有在原图顺序哈希与生成文本逐字一致时才可用于“描述方位正确但标签错误”统计；网格图的描述不沿用无网格图评审。

## 按网站 Protocol 2.0 接入

`POST /v1/predict` 保留原 `question`、有序 `images` 与 `response_constraint`。读取并校验本地图像及 SHA256；双图仍按现有约定交给低分辨率模型，题意由 planner 处理，不新增题意路由。

planner 负责理解问题并安排语义模型任务。语义模型自由生成后，最终答案层使用通用的“同模型原多模态 KV + 原问题 + 输出契约”接口；不能把 planner 模型的 KV 交给另一模型，也不能用重新编码描述替代原视觉上下文。对 enum 直接由 `response_constraint.values` 构建 token 掩码；single_choice 同时提供 `choices` 的含义，只输出合法标识；其余答案类型沿用各自序列化规则。无需根据开发集题目编号或固定英文问句编写特例。终结答案原位消费缓存，关闭后不能再复用该会话。

本轮十标签是内部实验集合。当前实际变化请求只包含九个区域，不能擅自把 `no_change` 加入网站允许集合：

- 若未来请求明确包含无变化选项，按其原字符串进行约束解码并返回。
- 若内部判为无变化而网站只允许九个区域，保留冲突诊断，最多用原双图和原问题重新确认一次；只在可确认区域时返回合法标签。仍无依据则走已有受控错误路径，不能将无变化固定映射成 center 或任意区域。
- 最终回复只包含 `protocol_version`、原样回显的 `request_id`、`item_id` 和 `answer`；内部描述、无变化信号和推理轨迹写本地诊断日志。

```json
{
  "protocol_version": "2.0",
  "request_id": "原请求值",
  "item_id": "原请求值",
  "answer": "top_left"
}
```

先用本轮结果确定变化识别与文本位置转换的表现，再决定是否接入。约束解码保证格式，不保证语义；自然无变化样本、多个变化簇与区域边界仍需要独立验证。
