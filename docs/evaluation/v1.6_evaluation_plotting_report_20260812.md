# v1.6 统一评测与绘图阶段汇报

日期：2026年8月12日  
代码分支：`feature/evaluation-v1.6-p0`  
当前基础提交：`93b2c85 feat(evaluation): add v1.6 explicit LEVIR decision`；绘图兼容更新将在本次整理后追加提交。

## 1. 工作概况

当前评测工作已经形成一套面向仓库现有任务的统一离线评测框架，覆盖：

- VRSBench单目标视觉定位（仓库中的 `detection + source_task=referring`，实质为Grounding）；
- 目标计数；
- VQA与场景分类；
- 遥感图像描述；
- LEVIR-CC变化二分类与变化描述；
- 基于参考文本的高级语义诊断；
- 同数据集、同样本ID条件下的模型配对比较；
- 汇总结果、逐样本结果、置信区间、错误清单和统一绘图。

v1.6相对v1.5最主要的变化，是针对负责人提出的“变化检测回答判定标准过严”问题，将“是否发生变化”和“发生了什么变化”从评测机制上拆开：

1. 原变化描述仍保存在 `prediction` 中，用于描述质量评测；
2. 对同一图像对追加一个独立二分类问题，要求模型输出 `0/1`；
3. 二分类指标优先使用独立输出，不再要求变化描述命中少量固定句式；
4. 旧预测文件缺少独立二分类字段时，仍可使用v1.5自然语言解析器兼容评测。

当前全部自动指标均属于内部评测指标；带有 `Approx` 的文本指标为轻量近似实现，不能作为数据集官方排行榜成绩。高级语义诊断只比较预测文本与参考文本，不读取图像，不能称为图像级事实正确率或图像级幻觉率。

## 2. 输入、输出与协议

### 2.1 Prediction JSONL基础字段

每条预测至少包含：

```json
{
  "id": "sample-1",
  "task_type": "captioning",
  "prediction": "model answer",
  "reference": "reference answer",
  "metadata": {
    "dataset": "VRSBench"
  },
  "inference_latency_ms": 12.5
}
```

LEVIR-CC的v1.6新预测增加：

```json
{
  "prediction": "A new building appeared.",
  "prediction_changeflag": 1,
  "binary_prediction": "1",
  "binary_prediction_parse_ok": true,
  "binary_prompt_version": "levir_semantic_change_binary_v1",
  "binary_inference_latency_ms": 18.4,
  "total_inference_latency_ms": 137.2
}
```

### 2.2 评测输出

- `evaluated_predictions.jsonl`：保留原始记录，并增加解析结果、判定来源和逐样本指标；
- `summary.json`：总体、分任务、分协议、分QA类型的汇总指标；
- `evaluation_manifest.json`：记录输入绝对路径、SHA256、契约版本、实现版本、运行环境和输出文件；
- 配对比较额外输出 `comparison_summary.json`、`paired_comparison.jsonl`、`improvements.jsonl`和`regressions.jsonl`；
- 绘图输出PNG/SVG和 `plot_manifest.json`。

### 2.3 协议边界

- VRSBench Grounding：连续归一化坐标内部协议；
- VRSBench Counting：整数解析和误差统计内部协议；
- VRSBench VQA/场景分类：规范化文本内部协议；
- VRSBench Caption：单参考轻量近似文本协议；
- LEVIR-CC：独立二分类优先、变化描述并行评测的v1.6协议；
- 多目标Detection mAP、像素级变化检测IoU/Dice和官方VRSBench Grounding profile当前未实现。

## 3. 通用质量与效率指标

| 指标 | 含义 | 采用原因 | 方向 |
|---|---|---|---|
| Num Samples | 实际进入评测的样本数 | 确认评测分母，防止漏样本 | 仅统计 |
| Task Distribution | 各任务样本数量 | 判断总体分数是否被某一任务数量主导 | 仅统计 |
| Protocol Distribution | 各评测协议样本数量 | 检查协议路由是否正确 | 仅统计 |
| Empty Prediction Rate | 空回答占比 | 直接暴露生成失败或结果导出异常 | 越低越好 |
| Average Generation Character Length | 平均回答字符数 | 诊断输出过短、过长或模板漂移 | 诊断 |
| Parse Success Rate | 回答能够被任务解析器识别的比例 | 区分“模型答错”和“格式不可用” | 越高越好 |
| Mean Latency | 平均单样本推理延迟 | 反映总体推理成本 | 越低越好 |
| P50 Latency | 延迟中位数 | 降低极端慢样本对平均值的影响 | 越低越好 |
| P95 Latency | 95%样本不超过的延迟 | 反映尾部延迟和部署稳定性 | 越低越好 |
| Min/Max Latency | 最快与最慢样本延迟 | 辅助定位异常值 | 诊断 |
| Latency Sample Count | 有有效延迟数据的样本数 | 防止用少量延迟代表全部样本 | 仅统计 |

延迟只有在 `single_sample` 或 `batch_amortized_per_sample` 等测量语义一致、batch size一致时才允许跨模型比较。参数量、模型文件大小、峰值显存和吞吐率不能从Prediction JSONL推测，需要读取量化组的 `benchmark_report.json`。

## 4. Grounding评测指标

当前仓库的 `detection + source_task=referring` 是单目标视觉定位，不是多目标Detection，因此采用单框Grounding指标，而不使用mAP。

| 指标 | 含义 | 采用原因 | 方向 |
|---|---|---|---|
| JSON Object Extraction Rate | 能否从纯JSON、代码块或混合文本中提取JSON对象 | 检查输出格式是否满足部署接口 | 越高越好 |
| Grounding Parse Success Rate | 是否成功解析标签与单个边界框 | 将结构解析失败与定位错误分开 | 越高越好 |
| Valid Coordinate Rate | 边界框坐标是否合法且顺序正确 | 非法框无法用于实际定位 | 越高越好 |
| Label Exact Match Rate | 预测类别与参考类别完全一致的比例 | 检查“定位正确但类别错误” | 越高越好 |
| Continuous Mean IoU | 预测框与参考框交并比的全样本均值；非法框记0 | 定位任务最常见的重叠质量指标，并对格式失败施加惩罚 | 越高越好 |
| Continuous Mean GIoU | 在IoU基础上考虑不相交框之间的距离；非法框记-1 | IoU为0时仍能区分“接近”和“相距很远” | 越高越好 |
| Mean Normalized Center Distance | 两个框中心距离除以单位图像对角线；非法框记1 | 反映目标中心偏移，对小目标特别有解释力 | 越低越好 |
| Acc@0.5 | IoU不低于0.5的样本比例 | 常用中等严格定位阈值 | 越高越好 |
| Acc@0.7 | IoU不低于0.7的样本比例 | 检查更精确的定位能力 | 越高越好 |
| Label+IoU Accuracy@0.5 | 类别正确且IoU不低于0.5 | 避免只框对位置但类别错误 | 越高越好 |
| Repository Mean IoU on Valid | 只在有效坐标样本上计算IoU | 与仓库历史口径兼容，不作为严格主指标 | 越高越好 |

选择这组指标的原因是：格式正确率、类别正确率和空间定位精度分别统计，能够定位问题究竟来自输出格式、语义类别还是边界框位置，而不是只用一个Mean IoU掩盖失败原因。

## 5. Counting评测指标

Counting解析器支持整数、简单英文数字、自然语言计数和 `{"count": 2}` 等形式。解析失败在Exact Accuracy和±1 Accuracy中按错误计入全样本分母。

| 指标 | 含义 | 采用原因 | 方向 |
|---|---|---|---|
| Number Parse Success Rate | 成功提取唯一、非负整数的比例 | 判断模型是否遵守计数输出要求 | 越高越好 |
| Exact Count Accuracy | 预测数量完全正确的比例 | 最直观、最严格的计数质量 | 越高越好 |
| Accuracy Within ±1 | 绝对误差不超过1的比例 | 遥感密集或小目标计数中反映近似可用性 | 越高越好 |
| MAE on Parsed | 已解析样本的平均绝对误差 | 误差单位直观，反映平均相差几个目标 | 越低越好 |
| RMSE on Parsed | 已解析样本均方根误差 | 对少量严重计数错误惩罚更大 | 越低越好 |
| Mean Signed Error | 平均“预测数−参考数” | 正值表示系统性高估，负值表示系统性低估 | 越接近0越好 |
| MAPE | 非零参考样本上的平均绝对百分比误差 | 比较不同目标数量规模下的相对误差 | 越低越好 |

同时保留Exact、±1和连续误差，是因为单独使用Accuracy不能区分“差1个”和“差几十个”，单独使用MAE又不能直接说明严格正确率。

## 6. VQA与场景分类评测指标

文本标准化过程包括：转小写、去引号和标点、压缩空格。

| 指标 | 含义 | 采用原因 | 方向 |
|---|---|---|---|
| Exact Match | 原始答案完全一致 | 最严格地检查答案和输出格式 | 越高越好 |
| Micro Normalized Accuracy | 标准化后完全一致的全样本准确率 | 避免大小写、标点等无关差异造成误判，是当前主指标 | 越高越好 |
| Token F1 | 预测与参考token集合的精确率和召回率调和平均 | 为部分正确的短文本答案提供连续诊断 | 越高越好 |
| Normalized Edit Similarity | 标准化文本的字符编辑相似度 | 识别拼写、小幅表达差异和接近答案 | 越高越好 |
| Keyword Hit | 参考关键词是否出现在预测中 | 快速诊断是否提及核心答案，但容易宽松，只作辅助 | 越高越好 |
| Macro QA-Type Accuracy | 先计算每种QA类型准确率，再对类型等权平均 | 防止object quantity等大类掩盖reasoning等小类短板 | 越高越好 |
| Per-QA-Type Accuracy | 按object quantity、position、color、reasoning、scene type等分类准确率 | 直接定位需要进行数据增强的任务短板 | 越高越好 |

其中Keyword Hit、Token F1和编辑相似度均属于内部诊断，不能称为VRSBench官方语义Accuracy。正式结论优先使用Normalized Accuracy，并配合按QA类型分解。

## 7. Caption与文本型变化描述指标

| 指标 | 主要衡量内容 | 采用原因 | 方向 |
|---|---|---|---|
| BLEU-1 Approx | 单词级精确匹配 | 检查对象和关键词是否覆盖 | 越高越好 |
| BLEU-2/3/4 Approx | 2至4元连续短语匹配 | 随阶数升高逐步检查局部语序和短语结构 | 越高越好 |
| Corpus BLEU-1/2/3/4 Approx | 在整个语料上统计截断n-gram并加入长度惩罚 | 避免逐样本平均对极短文本过度敏感 | 越高越好 |
| ROUGE-L F1 Approx | 基于最长公共子序列的覆盖与顺序相似性 | 对自然语言描述的措辞变化比严格n-gram更宽容 | 越高越好 |
| METEOR Exact Approx | 兼顾词级精确率、召回率和片段惩罚 | 补充BLEU偏重精确率的局限 | 越高越好 |
| chrF Approx | 字符n-gram F分数 | 对词形、拼写和分词差异较稳健 | 越高越好 |
| CIDEr-D Single-Reference Approx | 使用语料IDF强调有区分度的n-gram并抑制常见套话 | 更关注描述是否包含有信息量的内容 | 越高越好 |
| Average Prediction Token Count | 预测平均长度 | 诊断模型是否过短、过长或模板化 | 诊断 |
| Average Reference Token Count | 参考答案平均长度 | 为长度比较提供基准 | 诊断 |
| Length Ratio | 预测长度与参考长度之比 | 判断指标变化是否只是输出长度变化造成 | 越接近1通常越合理 |

这些指标采用互补组合：BLEU关注局部精确匹配，ROUGE-L关注覆盖和顺序，METEOR兼顾精确率与召回率，chrF降低分词影响，CIDEr-D强调信息性。由于当前通常只有单条参考描述，所有指标都明确标记为内部近似值。

LEVIR-CC变化描述同时计算：

- 全部样本描述指标；
- `changeflag=1`真实发生变化子集的描述指标。

单独报告正样本子集，是为了避免大量固定“无变化”参考句提高整体文本分数，从而掩盖模型对真实变化内容的描述能力。

## 8. LEVIR-CC变化二分类指标

### 8.1 数据与解析质量

| 指标 | 含义 | 采用原因 | 方向 |
|---|---|---|---|
| Changeflag Valid Rate | 参考 `metadata.changeflag` 为合法整数0/1的比例 | 保证二分类参考标签有效 | 应为100% |
| Binary Parse Success Rate | 成功取得模型0/1判定的比例 | 区分格式失败和分类错误 | 越高越好 |
| Explicit Binary Decision Rate | 使用独立 `prediction_changeflag` 或 `binary_prediction` 的比例 | 证明v1.6实际使用了P0，而非旧Caption回退 | 应接近100% |
| Caption Fallback Decision Rate | 仍从变化描述兼容解析的比例 | 识别旧预测文件或未接入P0的推理流程 | 新结果应接近0% |
| Binary/Structured/No-change Parse Mode Rates | 各类解析模式的占比 | 追踪模型输出格式和旧解析器行为 | 诊断 |

### 8.2 二分类质量

约定“有变化”为正类：

- TP：真实有变化且预测有变化；
- TN：真实无变化且预测无变化；
- FP：真实无变化但预测有变化；
- FN：真实有变化但预测无变化。

| 指标 | 含义 | 采用原因 | 方向 |
|---|---|---|---|
| Accuracy | `(TP+TN)/全部可比较样本` | 总体正确率，直观但可能受类别比例影响 | 越高越好 |
| Balanced Accuracy | 有变化召回率与无变化召回率的平均 | 当两类数量不均衡或模型偏向单一类别时更可靠 | 越高越好 |
| Change Precision | `TP/(TP+FP)` | 预测为有变化时有多少是真的，直接反映误报 | 越高越好 |
| Change Recall | `TP/(TP+FN)` | 真实变化中有多少被发现，直接反映漏检 | 越高越好 |
| Change F1 | Precision与Recall的调和平均 | 在误报和漏检之间提供综合评价 | 越高越好 |
| No-Change Recall / Specificity | `TN/(TN+FP)` | 专门衡量无变化样本能否正确识别，是负责人反馈问题的关键指标 | 越高越好 |
| Negative Predictive Value | `TN/(TN+FN)` | 预测为无变化时有多少是真的 | 越高越好 |
| False Positive Rate | `FP/(FP+TN)` | 无变化样本被误报为有变化的比例 | 越低越好 |
| False Negative Rate | `FN/(FN+TP)` | 有变化样本被漏报为无变化的比例 | 越低越好 |
| MCC | 综合TP/TN/FP/FN的相关系数，范围通常为-1至1 | 对类别不均衡和“全部预测同一类”更敏感 | 越接近1越好 |
| Cohen’s Kappa | 扣除随机一致后的分类一致性 | 避免仅靠类别比例获得看似较高的Accuracy | 越高越好 |
| Change Prevalence | 真实有变化样本比例 | 解释数据本身类别分布 | 仅统计 |
| Predicted Change Rate | 模型预测有变化的比例 | 直接暴露“几乎全部预测为有变化”或“几乎全部无变化” | 应接近真实比例 |

采用Accuracy、Balanced Accuracy、F1、MCC、Kappa和完整混淆矩阵的原因，是任何单一指标都可能掩盖模型偏置。例如模型全部预测为“有变化”时，Change Recall可能很高，但Specificity、MCC、Kappa和TN会明显暴露问题。

## 9. 高级语义诊断指标

高级语义模块从预测文本和参考文本中按遥感领域词表抽取对象、数量、空间关系和变化事件。

| 指标 | 含义 | 用途 |
|---|---|---|
| Object Precision | 预测提到的对象中，有多少也出现在参考文本 | 诊断参考文本不支持的对象提及 |
| Object Recall | 参考对象中，有多少被预测覆盖 | 诊断对象遗漏 |
| Object F1 | Object Precision与Recall的综合 | 综合对象事实覆盖情况 |
| Reference-Unsupported Object Rate | 预测对象未被参考文本支持的比例 | 内部“疑似无依据提及”诊断 |
| Object Omission Rate | 参考对象未被预测提及的比例 | 诊断描述遗漏 |
| Count Consistency Accuracy | 可对齐对象的数量是否与参考文本一致 | 检查文本内部计数事实 |
| Spatial Relation Precision/Recall/F1 | 空间关系三元组的匹配质量 | 检查left/right/near等关系描述 |
| Spatial Relation Accuracy | 可比较空间关系是否正确 | 提供更直观的关系正确率 |
| Change Event Precision/Recall/F1 | 新增、移除、建造、变化等事件与参考文本的匹配 | 诊断变化描述是否覆盖关键事件 |

采用这组指标是为了弥补BLEU、ROUGE等表面文本相似度不能直接解释“对象、数量和关系是否说对”的不足。但其证据来源仍是参考文本，不是原图：

- `Reference-Unsupported Object Rate`不能直接称为图像幻觉率；
- 参考描述可能不完整，因此未被参考文本提及不等于图像中不存在；
- 真正的图像级事实正确率仍需要目标检测器、图文判别模型、人工标注或多模态裁判模型。

## 10. 模型配对比较指标

在基线与候选模型ID集合、任务类型和参考答案完全一致时，工具进行逐样本配对比较：

- Grounding：IoU、GIoU、中心距离、Acc@0.5/0.7、Label+IoU Accuracy；
- Counting：绝对误差、百分比误差、Exact Accuracy和±1 Accuracy；
- VQA/场景分类：Exact Match、Normalized Accuracy、Token F1和编辑相似度；
- Caption：BLEU-1/2/3/4、ROUGE-L、METEOR、chrF和CIDEr-D。

每项指标输出：

| 指标 | 含义 | 采用原因 |
|---|---|---|
| Improvement Mean | 候选模型相对基线的平均改善；代码统一转换为正值表示改善 | 便于不同方向的指标统一解释 |
| Relative Change | 相对基线的变化幅度 | 衡量改善相对原水平的大小 |
| Wins / Ties / Losses | 逐样本改善、持平、退化数量 | 避免均值被少数极端样本主导 |
| Paired Bootstrap 95% CI | 对逐样本差值进行配对Bootstrap得到的95%置信区间 | 判断观察到的提升是否稳定；跨0表示差异仍不确定 |

配对比较比简单比较两个汇总分数更有说服力，因为它保持同一样本成对，能够直接列出改善和退化样本，为后续错误分析和数据增强提供依据。

| VRSBench Core Metrics | Grounding、Counting、VQA、场景分类、Caption核心指标 | 多面板比较模型任务能力，避免不同量纲混在同一坐标轴 |
| Grounding IoU CDF | 逐样本IoU及0.5/0.7阈值 | 展示整个定位质量分布，而非只看均值 |
| Counting Error Distribution | 绝对误差、正负误差、正确/±1/大误差比例 | 判断高估、低估和长尾大错误 |
| VQA Accuracy by QA Type | 各QA类型Normalized Accuracy与样本量 | 定位object quantity、position、reasoning等短板 |
| Caption Quality and Length | BLEU、ROUGE-L、chrF、CIDEr-D和Length Ratio | 判断描述质量变化是否由输出长度造成 |
| Semantic Reference-Text Diagnostics | Object、Count、Spatial Relation等规则指标 | 展示参考文本层面的语义遗漏和不一致 |
| Paired Improvement + 95% CI | Improvement Mean及Bootstrap区间 | 判断候选模型是否稳定改善 |
| Win/Tie/Loss | 各任务代表指标的逐样本胜平负 | 展示改善覆盖面和退化风险 |
| LEVIR-CC Confusion Matrix | TP、TN、FP、FN及按真实类别归一化比例 | 最直接展示是否偏向全部预测有变化 |
| LEVIR-CC Binary Metrics | Accuracy、Balanced Accuracy、Precision、Recall、F1、MCC、Kappa、FPR、FNR | 全面评价二分类质量 |
| LEVIR-CC Caption Metrics | 全样本与真实变化子集的文本指标 | 区分固定无变化句与真实变化描述能力 |
| Inference Latency | Mean、P50、P95 | 在测量口径一致时比较效率 |

绘图使用英文标签、色盲友好配色和PNG/SVG双格式；输入不足或延迟口径不一致时跳过相应图表，并把原因写入 `plot_manifest.json`，避免生成具有误导性的空图或不可比图。

## 12. 负责人反馈问题的解决方式

### 12.1 原问题

原评测从变化描述文本中寻找少量固定“无变化”句式。模型虽然表达了无变化，但只要措辞、时态或句子结构不同，就可能被判成有变化，导致假阳性异常增多，甚至出现“统计上几乎全部预测为有变化”。

### 12.2 v1.5兼容修复

v1.5扩大了自然语言解析能力：

- 支持时态、单复数、轻微措辞差异和多句全局无变化结论；
- 支持 `0/1` 与结构化JSON；
- 识别场景说明之后的全局无变化结论；
- 不使用简单关键词包含规则；
- `No building changed, but a road appeared`等复合描述仍判为有变化。

该修复让旧预测文件可以重新评测，但仍然属于“从Caption推断二分类”的兼容方案。

### 12.3 v1.6 P0机制修复

v1.6采用独立二分类推理：

1. 模型先正常生成变化描述；
2. 对同一图像对追加固定问题；
3. 提示词要求忽略光照、季节、分辨率、视角、配准噪声和临时物体；
4. 建筑新增、拆除、扩建、替换或移除视为语义变化；
5. 模型只回答 `0=无变化` 或 `1=有变化`。

评测优先级为：

1. 合法整数 `prediction_changeflag`；
2. 独立问题原始输出 `binary_prediction`；
3. 两者都不存在时，才对旧Caption进行兼容解析。

如果显式二分类字段存在但非法，评测会记录解析失败，不会偷偷使用Caption兜底。这样既解决了固定白名单过严的问题，也保证独立二分类失败能够被发现。

通过 `Explicit Binary Decision Rate`、`Caption Fallback Decision Rate`、`Predicted Change Rate`、Specificity、FPR、MCC和混淆矩阵，可以验证新流程是否真正生效，以及模型自身是否仍有“倾向预测有变化”的能力偏置。

## 14. 下一步推进计划

### P0：完成v1.6闭环

1. 在微调组已有服务器环境中拉取 `feature/evaluation-v1.6-p0`。
2. 先用10至20条LEVIR-CC样本运行独立0/1推理，检查：
   - `prediction_changeflag`均为合法整数0/1；
   - `binary_prediction_parse_ok`接近100%；
   - `explicit_binary_decision_rate`接近100%；
   - `caption_fallback_decision_rate`接近0%。
3. 小样本通过后运行完整1,333条LEVIR-CC验证集。
4. 使用v1.6重新计算混淆矩阵、Accuracy、Balanced Accuracy、F1、MCC、Kappa、FPR、FNR和变化描述指标。
5. 生成v1.6正式图表；旧Caption fallback结果作为历史诊断单独展示，不与v1.6结果进行同契约配对比较。

### P1：形成可用于方案分析的对照实验

1. 对基础模型、LoRA模型和量化模型使用完全相同的LEVIR-CC样本与v1.6协议；
2. 分析独立二分类带来的准确率变化与额外延迟；
3. 输出FP/FN错误清单，抽取典型误报和漏报样本；
4. 将VRSBench能力保持情况与LEVIR-CC新增能力放在同一份报告中，防止只优化变化检测而损伤原任务；
5. 使用配对Bootstrap区间说明差异是否稳定，而不是只比较单个汇总分数。

### P2：根据短板推进数据与模型改进

1. 若FPR仍高：增加无变化、季节差异、光照差异、轻微配准偏差等困难负样本；
2. 若FNR高：增加小建筑新增/拆除、局部变化和低对比度变化样本；
3. 若二分类正常但描述指标低：加强变化对象、动作和位置描述数据；
4. 若VQA某些QA-Type明显偏低：向数据组提供按类型的数据增强优先级；
5. 若量化后特定指标显著下降：与量化组联合定位层敏感度，并增加任务级Pareto图；
6. 若bit flip测试形成标准输出：扩展绘图适配器，增加层敏感度、故障强度—性能退化和保护前后恢复图。

## 15. 汇报结论

v1.6已经从机制上解决“无变化答案必须命中少量固定句式”的评测缺陷：是否变化改由针对图像对的独立0/1推理负责，变化Caption只负责描述内容；同时保留旧结果兼容，并通过判定来源、解析成功率、类别预测比例、混淆矩阵、Specificity、FPR、MCC等指标防止再次出现“全部判为有变化但单项Recall看起来正常”的误导。

当前评测指标体系、P0代码以及绘图/配对比较的v1.6兼容已经形成，但最终结论仍需要微调组在完整模型与LEVIR-CC环境中重新生成v1.6预测。下一阶段的首要工作是真实1,333条结果回放，随后再进行模型间对照、错误分析和数据增强。
