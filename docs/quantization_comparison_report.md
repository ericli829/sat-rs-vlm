# INT8 量化前后模型质量对比报告

## 1. 实验概述

| 项目 | 说明 |
|------|------|
| 测试模型 | Qwen3-VL-2B-Instruct + LoRA (r=16) |
| 数据集 | VRSBench (50 条 VQA 样本) |
| 量化方法 | PyTorch Dynamic INT8 Quantization |
| 评估日期 | 2026-08-10 |

## 2. 模型配置

| 配置 | 量化前 (Merged) | 量化后 (INT8) |
|------|----------------|---------------|
| 精度 | FP32 | INT8 |
| 模型大小 | 7.94 GB | 3.15 GB |
| 压缩比 | 1.0× | **2.51×** |

## 3. 性能对比

### 3.1 推理速度

| 指标 | 量化前 (FP32) | 量化后 (INT8) | 变化 |
|------|---------------|---------------|------|
| 平均推理延迟 | 4892 ms | 2295 ms | **-53.1%** |
| 相对加速 | 1.0× | **2.13×** | +113% |

### 3.2 VQA 任务质量

| 指标 | 量化前 (FP32) | 量化后 (INT8) | 变化 |
|------|---------------|---------------|------|
| Keyword Hit Rate | 66.0% | 46.0% | **-20.0%** |
| Exact Match Rate | 0.0% | 0.0% | 0.0% |
| Average Generation Length | 17.32 | 18.58 | +7.3% |
| Empty Prediction Rate | 0.0% | 0.0% | 0.0% |

## 4. 综合分析

### 4.1 量化优势

1. **推理速度显著提升**
   - INT8 量化使推理速度提升 2.13 倍，平均延迟从 4892ms 降至 2295ms
   - 推理时间减少约 53%，更适合实时应用

2. **内存占用大幅降低**
   - 模型大小从 7.94GB 压缩至 3.15GB，节省约 60% 存储空间
   - 显存占用显著降低，可在更低端的 GPU 上运行

### 4.2 量化劣势

1. **质量有所下降**
   - VQA 任务的 Keyword Hit Rate 下降 20 个百分点（66% → 46%）
   - 这是 INT8 量化的典型 trade-off：速度换精度

2. **对复杂任务的影响**
   - 对于需要精确数值或复杂推理的任务，量化损失可能更明显

### 4.3 适用场景建议

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| 实时推理/边缘部署 | INT8 量化版 | 速度优先，资源受限 |
| 离线分析/研究 | Merged FP32 | 质量优先，不计成本 |
| 批量处理 | INT8 量化版 | 吞吐量优先 |

## 5. 结论

| 维度 | 量化前 (FP32) | 量化后 (INT8) |
|------|---------------|---------------|
| 推理速度 | ★★★☆☆ (较慢) | ★★★★★ (快 2.13×) |
| 内存占用 | ★★☆☆☆ (7.94GB) | ★★★★★ (3.15GB) |
| 任务质量 | ★★★★☆ (66% hit) | ★★★☆☆ (46% hit) |

**量化决策建议：**

- 如果部署环境对**延迟敏感**且资源有限，INT8 量化版是更好的选择
- 如果对**任务质量要求较高**，建议保留 FP32 版本
- 对于本项目的遥感图像理解任务，INT8 量化的速度提升（2.13×）显著，质量损失（20%）可接受

## 6. 进一步优化建议

1. **混合精度量化**：仅量化 LLM 部分，保留 Vision Encoder 为 FP16
2. **量化感知训练 (QAT)**：在训练时引入量化，减少最终质量损失
3. **阈值调优**：根据任务特性调整量化范围
4. **评估扩展**：在更多任务类型（captioning、detection、counting）上进行评估
