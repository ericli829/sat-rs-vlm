# VLM-FO1 counting evaluation integration

This integration evaluates the official `om-ai-lab/VLM-FO1` model through a
long-lived JSONL sidecar.  The main `sat-rs-vlm` interpreter never imports
`torch`, `transformers`, UPN, or the official `vlm_fo1` package for this path.

## Architecture

```text
evaluation-v1.8 tier JSONL
        |
        | id, image, question, target_phrase (never reference)
        v
vlm_fo1_worker.py (VLM_FO1_PYTHON / isolated vlm-fo1)
        |
        | proposal evidence + FO1 region indexes + count
        v
predictions.jsonl -> formal counting_protocol.py -> metrics/diagnostics
```

The worker is long-lived: one process loads UPN and FO1 once, then handles
one JSON request per line.  Any failure is returned with `status=failed` and a
`failure_stage`; no parse failure is converted into a guessed count.

## Source audit

The official source audit is generated by:

```powershell
& $py scripts/integrations/audit_vlm_fo1_source.py `
  --model-dir D:\Desktop\tzb-2026\VLM-FO1-3B-v01
```

It writes `reports/integrations/vlm_fo1_source_audit.json` and `.md`.  The
audited public path is UPN (the paper's OPN is not released): score threshold
`0.3`, implementation-default NMS `0.8`, top-k `100`, original pixel `xyxy`
boxes, official `OD_Counting_template`, and greedy generation with
`max_tokens=4096`, `top_p=0.05`, `temperature=0.0`, `do_sample=false`.

## Isolated environment

Do not install the official requirements into `rs-vlm`.  From a clean host:

```bash
git clone https://github.com/om-ai-lab/VLM-FO1.git "$VLM_FO1_ROOT"
conda env create -f sat-rs-vlm/environments/vlm_fo1/environment.yml
conda run -n vlm-fo1 python -m pip install -v -e "$VLM_FO1_ROOT/detect_tools/upn/ops"
```

Set these variables before a real run:

```bash
export VLM_FO1_ROOT=/path/to/VLM-FO1
export VLM_FO1_PYTHON=/path/to/conda/envs/vlm-fo1/bin/python
export VLM_FO1_MODEL=/path/to/VLM-FO1-3B-v01
export VLM_FO1_UPN_CHECKPOINT=/path/to/upn_large.pth
export VLM_FO1_CACHE_DIR=/path/to/cache
export VLM_FO1_IMAGE_ROOT=/path/to/dataset-parent
```

Validate the environment without touching the rs-vlm interpreter:

```bash
"$VLM_FO1_PYTHON" sat-rs-vlm/environments/vlm_fo1/check_environment.py
```

## Prompt profiles

`plain` sends the original VRSBench question; `integer` adds an integer-only
instruction; `json` uses the repository's `{"count": integer}` protocol;
`official_fo1` uses the audited official template and region-index output
contract.  The profile is recorded in every row and in `provenance.json`.

Target extraction is open-vocabulary and deterministic.  Category-level,
comparative, generic-object, lane, and relationship questions are returned as
`target_status=unsupported`; the evaluator does not map them to the existing
detection taxonomy and never reads the reference answer.

## Outputs and evidence

Every sample keeps:

* raw proposal boxes and scores;
* selected region indexes and selected boxes/scores;
* raw FO1 output and textual-count diagnostic;
* final selected-region count, status, failure stage, and latencies.

Each run writes `predictions.jsonl`, `metrics.json`, `summary.md`,
`provenance.json`, and `fo1_diagnostics.json`.  Counting metrics are delegated
to `sat_rs_vlm.evaluation.counting_protocol.summarize_exact_cardinality_counting`
and use the same exact-cardinality eligibility and count bins as evaluation-v1.8.

## Smoke and formal commands

Use the mock sidecar first (no checkpoint or GPU) to validate the entire JSONL
boundary:

```powershell
$py = 'C:\Users\Ericoneabc\AppData\Local\Microsoft\WindowsApps\python.exe'
& $py scripts/evaluation/evaluate_vlm_fo1.py `
  --config configs/eval/vlm_fo1_e_count_v2.yaml `
  --backend mock --worker-python $py --max-samples 4 `
  --image-root F:\VIT-data
```

After the isolated environment and UPN checkpoint are validated, the focused
run is:

```bash
python scripts/evaluation/evaluate_vlm_fo1.py \
  --config configs/eval/vlm_fo1_e_count_v2.yaml \
  --worker-python "$VLM_FO1_PYTHON" \
  --image-root "$VLM_FO1_IMAGE_ROOT"
```

The full VRSBench Quantity scope (the same evaluator core, filtered from the
multisource evaluation file) is:

```bash
python scripts/evaluation/evaluate_vlm_fo1.py \
  --config configs/eval/vlm_fo1_full_vrsbench_quantity.yaml \
  --worker-python "$VLM_FO1_PYTHON" \
  --image-root "$VLM_FO1_IMAGE_ROOT"
```

Here `python` is the existing `rs-vlm`/evaluation interpreter; only the
long-lived worker is launched with `VLM_FO1_PYTHON`.

The full-scope selector keeps the reproducible 6,131-row VRSBench Quantity
population (counting rows with parseable references).  The shared formal
counting protocol may report a smaller exact-cardinality metric denominator for
non-cardinality wording; that exclusion is recorded in `metrics.json` rather
than silently changing the input population.

For `E_COUNT_V2`, the raw counting population is 377 and the formal
exact-cardinality denominator is expected to be 327; the config checks the raw
population before inference and the shared protocol reports the eligible
denominator.

No formal run or large checkpoint download is started by repository tests.

## Ensemble comparison

`scripts/evaluation/compare_counting_predictions.py` aligns by id, rejects
duplicates/reference mismatches, and reports pairwise agreement, correctness
overlap, oracle accuracy, majority vote, and median vote.  It does not search
router thresholds; any future development-only threshold experiment must be
marked explicitly and must not be reported as a formal test result.

## Known limitations

The current public FO1 source does not release the paper's OPN detector, so
the baseline is UPN.  The downloaded local model directory contains model
weights separately from the source/config files; `VLM_FO1_MODEL` must point to
a complete model directory when the official worker is used.  GPU inference
and the UPN custom ops require the isolated Linux environment and are not part
of the Windows unit-test suite.
