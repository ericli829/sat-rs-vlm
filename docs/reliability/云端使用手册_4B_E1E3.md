# 4B Reliability 云端使用手册

适用分支：`lyz-reliability-v15-migration`。用于 Qwen3-VL-4B-Instruct 的真实 GPU fault injection、敏感性扫描和 E1/E2/E3 评测。

## 获取代码和环境

```bash
git clone -b lyz-reliability-v15-migration https://github.com/ericli829/sat-rs-vlm.git
cd sat-rs-vlm
git pull origin lyz-reliability-v15-migration
export PROJECT_ROOT=$PWD
export MODEL_ROOT=/root/autodl-tmp/models
export DATA_ROOT=/root/autodl-tmp/datasets
export OUTPUT_ROOT=/root/autodl-tmp/outputs
export QWEN3VL_4B_MODEL_DIR=$MODEL_ROOT/Qwen3-VL-4B-Instruct
export PYTHONPATH=$PROJECT_ROOT/src:$PROJECT_ROOT
```

模型必须是官方 `Qwen3-VL-4B-Instruct` 本地目录。不要把 2B 权重或 2B LoRA adapter 配给 4B。安装依赖后确认 CUDA：

```bash
python -m pip install -r environments/requirements-model.txt
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.device_count())"
```

没有 CUDA 时，真实扫描会被阻止，不会降级成 mock。

## 配置和 Preflight

推荐配置：

```text
configs/reliability/experiments/v15_sensitivity_4b.yaml
```

没有 4B adapter 时使用 `adapter_path: null`；不能使用 2B adapter。

```bash
python scripts/reliability/run_v15_sensitivity.py \
  --config configs/reliability/experiments/v15_sensitivity_4b.yaml \
  --environment autodl --run-id qwen3vl-4b-e1-pilot --preflight
```

Preflight 必须通过：模型、processor、数据集、E1 文件、tier manifest、SHA256、样本数和 CUDA。

查看条件计划：

```bash
python scripts/reliability/run_v15_sensitivity.py \
  --config configs/reliability/experiments/v15_sensitivity_4b.yaml \
  --environment autodl --run-id qwen3vl-4b-e1-pilot --dry-run
```

`coverage_first` 会先覆盖所有目标、三种 bit-plane 和代表层。层数从 safetensors 自动发现；4B 通常是语言层 0-35、视觉 block 0-23，不要写死旧的 0-27。

## Pilot-only

第一次只跑小规模 pilot：

```bash
python scripts/reliability/run_v15_sensitivity.py \
  --config configs/reliability/experiments/v15_sensitivity_4b.yaml \
  --environment autodl --run-id qwen3vl-4b-e1-pilot \
  --pilot-only --activation-guard --activation-guard-mode research
```

pilot 应覆盖：`language_model`、`attention`、`mlp`、`vision_encoder`、`visual_blocks`、`visual_merger`、`embeddings` 和（存在 4B adapter 时）`lora_adapter`，以及 `sign`、`exponent`、`mantissa`。

## 结果检查和续跑

```bash
python scripts/reliability/plot_results.py \
  --sensitivity-root <RUN_DIR> --output <RUN_DIR>/plots
```

检查：

```text
condition_plan.json
sensitivity_progress.json
sensitivity_report.json
conditions/*/fault_injection_summary.json
conditions/*/comparison/comparison.json
```

`bit_index_changed_rate.png` 必须按 `records[].dtype` 解读。float16、bfloat16、float32 的指数位 bit index 不同，不能混合绝对 bit index。

pilot 通过后用同一 run id 续跑：

```bash
python scripts/reliability/run_v15_sensitivity.py \
  --config configs/reliability/experiments/v15_sensitivity_4b.yaml \
  --environment autodl --run-id qwen3vl-4b-e1-pilot \
  --resume --activation-guard --activation-guard-mode research
```

`--resume` 会校验 condition plan 和 evaluation identity。tier、评测文件或 hash 改变时必须换新的 run id。

## E1/E2/E3 晋级

```text
E1 pilot -> E1 full -> 按敏感性筛选高风险条件 -> E2 -> 少量关键条件 E3
```

不同 tier 的结果不能直接混合。每个结果必须保留 tier、manifest、eval 文件 SHA256、样本数、模型 checkpoint 和 git commit。

## 常见兼容问题

### selector 未命中

```bash
python scripts/reliability/verify_model_selector_alignment.py \
  --model "$QWEN3VL_4B_MODEL_DIR" \
  --output reports/reliability/qwen3vl_4b_selector_alignment.json
```

应确认 `visual_blocks` 和 `visual_merger` 的命中数量大于 0。

### ActivationGuard 触发

研究扫描用 `research` 模式，异常会记录为 `completed_guarded` 并继续下一个 condition。部署验证才使用 `deployment` 模式。

### 空白热力图

空白表示未扫描，不表示低风险。检查图中的 `n` 和 `sensitivity_progress.json`。

### tier hash 不一致

不要修改 JSONL、删除 manifest 后继续 resume。重新同步数据，或使用新 run id。

## 需要上传的内容

上传代码、配置、固定 tier 资产：

```text
src/ scripts/ configs/ data/evaluation/tiers/
```

不要上传模型权重、`reports/`、`outputs/`、`.cache/` 或 `.mplconfig/`。扫描结果单独保存 run 目录中的配置、condition plan、progress、summary、plots 和 logs。

本实验是软件研究工具，不等同于硬件 ECC 或航天器件级容错认证。
