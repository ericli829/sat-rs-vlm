# 单粒子翻转敏感性分析与分级保护实施路线

## 默认工程

`team/sat-rs-vlm` 的 `lyz-reliability-v15-migration` 分支是当前默认工程。旧的 `single_event_upset` 目录只作为历史基线和结果参考，不再作为默认开发入口。

## 默认实验口径

默认 v1.5 实验现在按语言模型层逐层扫描：

- 目标模块：语言模型层内其他参数、Attention、MLP、视觉编码器、Embedding/`lm_head` 和 LoRA Adapter。
- 层号：Attention、MLP 和 LoRA 按语言模型第 0 到第 27 层扫描；视觉编码器和 Embedding 扫描其全部匹配参数。
- 故障类型：sign、exponent、mantissa 可分别指定。
- 故障强度：1、10、100 bit。
- 每个条件使用多个 seed 重复。
- LoRA Adapter 既作为模型的一部分加载，也纳入默认参数故障扫描。
- KV Cache 和激活值不属于持久化模型参数，不能直接套用参数 bit flip；它们通过 Activation Guard 和独立运行时故障实验接入保护评估。

上述目标默认都会纳入扫描；只有在用户明确指定 `--targets` 时，才用指定目标替换默认的全覆盖集合。

## 实验闭环

```text
逐层故障注入
  -> clean/fault 配对推理
  -> 输出质量与异常统计
  -> 层 × bit-plane 可视化
  -> 高风险位置局部复验
  -> 按风险分配保护资源
```

## 结果记录

每个条件必须记录模型、Adapter、数据集、层号、模块、参数名、bit-plane、bit index、翻转数量、seed、输出质量和运行成本。已经完成的条件直接复用，失败或缺失条件单独重跑。

## 可视化重点

1. 层号 × bit-plane 热力图：颜色表示输出变化率、非法率或任务指标下降。
2. Attention 与 MLP 的模块对比图。
3. Q/K/V/O 及 MLP 投影类型对比图。
4. 具体 bit index 与输出质量曲线。
5. 无保护、局部保护和全面保护的收益/成本图。

## 节省资源的执行方式

- clean 基线只运行一次。
- 先用少量样本粗扫所有层，再对高风险层增加样本和 seed。
- 保护策略变化只复用已有 fault 输出，不重复模型推理。
- 通过条件 ID、状态文件和 `--resume` 实现断点续跑。
- 对异常结果支持单层、单模块、单 bit-plane、单 bit index 的局部重跑。

## 分资源保护

- 低风险层：记录和监测。
- 中风险层：输出检查、重试和必要时局部重算。
- 高风险层：SHA-256 校验、热备/可信副本、定期 scrub 和严格激活检测。
- 关键风险：故障阻断、可信副本恢复，并标记需要平台级 ECC/TMR 的对象。

初始优先关注 exponent 和 sign，但最终保护优先级必须由真实实验数据决定，不能只根据浮点格式推断。

## 可信边界

smoke 结果只证明流程；真实 GPU 结果才用于敏感性结论。单个随机 seed 只用于定位，正式结论需要多个 seed、统一数据集和置信区间。软件副本、校验和、输出检测及激活监测不等同于硬件 ECC/TMR。
